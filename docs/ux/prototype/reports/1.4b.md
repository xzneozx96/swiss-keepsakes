# 1.4b: C03 add-to-cart feedback (fly-to-cart and toast)

The owner asked for an animation of the item dropping into the cart and a toast that confirms the add. Before this change, an add only set `added` in `use-gift-detail.ts`. The app had no toast region and no animated badge.

## 1. What I built

- **Flight.** When an add succeeds from the add-to-cart sheet, a 40px round thumbnail of the product's first photo flies from the sheet's add button to the cart button that is on screen.
  - It moves on a curve for 650ms. The horizontal part eases out. The vertical part eases in to 28px above the button, then the thumbnail drops in and fades out.
  - The animation uses the Web Animations API on a fixed node appended to `body`. It changes transform and opacity only, so nothing shifts on the page.
  - **Target.** The flight goes to whichever `[data-cart-target]` is inside the viewport and not inside `[data-visible="false"]`. Unscrolled, that is the glass button on the photo. Scrolled, it is the `CompactBar` button.
  - **Skipped** when `prefers-reduced-motion: reduce` is set, or when no cart button is on screen.
- **Badge.** `CartButton` waits for the flight to land (`cartFlight()`) and then shows the new count. When the count goes up, the badge pops (scale 1 → 1.4 → 1, 300ms). The pop is skipped with reduced motion; the count still changes. The aria-label updates at once.
- **Toast.**
  - Uses HeroUI v3 `toast.success`. Title: "Added to cart" / "In den Warenkorb gelegt". Description: "{name} · {variant} × {quantity}". Action: "View cart" / "Zum Warenkorb", which opens /cart.
  - It auto-dismisses after 6s, and the timer pauses on hover or focus. The coordinator approved this on 13 Oct; see the D2 exception below.
  - A new add closes the previous cart toast, so toasts never stack.
- **Toast region.** A new `AppToasts` is mounted once in `__root.tsx`.
  - Placement is bottom, lifted to `safe-area + 96px`, so the toast clears the C03 bottom bar (27px gap at 375px).
  - Width is `min(398px, 100vw − 2rem)`, which stays inside the 430px guest frame. HeroUI's 460px minimum from `sm` is removed.
  - It renders the HeroUI default toast parts with translated labels, because HeroUI's close label is hard-coded "Close". The region is labelled "Notifications" / "Benachrichtigungen" and the close button "Close" / "Schliessen".
- **Screen readers.** The toast is an alertdialog containing an `alert`, so it is announced.

- The toast box is at y 608–716; the bottom bar top is at 743.

- There were no console errors.

Second script (`extra.mjs`):
- **Keyboard.** Pressing Enter on the sheet's add button closes the drawer, and focus returns to the bar's "Add to cart" button. The toast does not steal focus. Alt+T (HeroUI's hotkey) moves focus to the "Notifications" region, Tab reaches the toast, and Tab again reaches "View cart".
- **Badge pop.** 2 animations per add, one on each of the 2 `CartButton` instances (the hidden instance animates unseen). 0 with reduced motion.
- **Close button.** Clicking "Close" removes the toast.
- **Auto-dismiss.** 0 toasts remain about 7s after the second add (pointer away from the toast).

## 5. Open questions for the owner

1. Do you accept the D2 exception (auto-dismiss after 6s even though the toast has an action)? The coordinator approved it pending your view.
2. Screen readers now hear the add twice: the bar's existing `aria-live` "Added to cart" and the toast alert. I kept both, because the brief said not to change the existing flow. If you want one announcement, the bar's live region can be removed.
3. The toast appears as soon as you add, while the item is still flying. The alternative is to show it when the item lands, about 650ms later. I chose immediate so that feedback never waits on the animation.
