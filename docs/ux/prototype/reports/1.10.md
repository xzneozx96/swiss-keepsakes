# Step 1.10 report: M03 Merchant gift orders list

## 1. What I built

M03 Gift orders at `#/store/orders`. It replaces the placeholder.

- **Tabs:** the 7 status tabs from spec §3.2, each with a count. It uses HeroUI Tabs (primary). The list scrolls sideways with chevrons and a fade on phones, and also at 1024px, where seven tabs don't fit beside the sidebar. A tab selected through a deep link scrolls into view.
- **`?status=` search param:** selects the tab. Values (coordinator-approved, exported as `ORDER_TABS` from `front-end/src/features/merchant/orders/lib/order-tabs.ts`):

  | Value | Orders |
  | --- | --- |
  | `awaiting-confirmation` (default, no param) | requested |
  | `awaiting-payment` | accepted (M02 "overdue" links here) |
  | `preparing` | preparing |
  | `ready` | ready |
  | `owing` | handed_over |
  | `completed` | completed |
  | `cancelled` | cancelled and declined |

  An unknown value falls back to the default tab. Switching tabs replaces the history entry.
- **Phone:** one stacked card per order. Each card shows the reference, the guest name, a product summary ("1 × Kapellbrücke pocket knife", "+N more"), the progress StatusChip and the payment StatusChip, and the pickup date and place. The whole card is a link to M04.
- **From 1024px:** a HeroUI Table with 4 columns: Order (guest + ref), Gifts, Status (both chips stacked), Pickup (date + place). The row opens M04 by click or Enter.
- **Labels:** come only from T0 (`progressLabel(order, "staff")`, `paymentLabel(order, now)`, `formatLabel`). The page has no money logic of its own.
- **States:**
  - Skeleton on load (`useSimulatedLoading`).
  - Empty tab: shared EmptyState with one sentence and "Back to Today". With the seed, Balance owed has 0 orders, so this state is reachable.
- **Files created:**
  - `front-end/src/routes/store/orders/index.tsx` (list route `/store/orders/`; `orders.tsx` deleted so 1.11 can add `orders/$orderId.tsx` without a layout parent)
  - `front-end/src/features/merchant/orders/lib/order-tabs.ts`
  - `front-end/src/features/merchant/orders/hooks/use-merchant-orders.ts`
  - `front-end/src/features/merchant/orders/components/merchant-orders.tsx`
  - `front-end/src/features/merchant/orders/components/order-rows.tsx`
- **Files changed:** `src/i18n/en.ts` and `src/i18n/de.ts`, one `merchantOrders.*` block each.

**For 1.11:** rows link to M04 with a plain hash href, `orderDetailHref(order)`, which gives `#/store/orders/${order.id}`, e.g. `#/store/orders/sk-1042`. The route param is `order.id` (lowercase), not `order.ref`. I didn't use a typed Link because `$orderId` is not in the route tree yet, so tsc would fail. Once 1.11 creates `routes/store/orders/$orderId.tsx`, it can swap the helper for a typed Link.
