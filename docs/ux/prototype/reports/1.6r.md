# Step 1.6r report: C05 sign-in becomes a screen (owner review, part 1)

Owner verdict on 1.6, part 1: "design a proper auth screen with 2 column layout … sign in form … hero image, search internet for a lucerne related image". Part 2 (the Account redesign) belongs to 1.12r and is not covered here.

## 1. What I built

### C05 sign-in screen, route `/sign-in?returnTo=<path>`

- **Location:** a top-level route (`src/routes/sign-in.tsx`), outside `_guest`. `GuestShell` caps every `_guest` child at 430px, which rules out two columns. The prototype bar (language switch, Mail panel, Prototype controls) still shows because it lives in `__root`. There is no tab bar, since this is a focused task.
- **Phones and tablets (below 1024px):** the screen redraws the guest frame: a 430px column centred on `bg-default/60`.
  - **Hero:** the Lucerne photo sits on top, `clamp(220px, 36dvh, 320px)` tall, with a round Back button (`BackButton tone="pill"`) and a short shade behind it.
  - **Form:** sits on a sheet with 28px rounded top corners that overlaps the photo by 28px.
- **From 1024px:** two columns, `5fr / 7fr`.
  - **Left column:** the Swiss Keepsakes wordmark (links home) and a "Back" text button on one row. The form is centred vertically at most 400px wide.
  - **Right column:** the photo fills the column, inset 12px with 28px corners. A bottom scrim carries the place name in the serif ("Chapel Bridge and Water Tower, Lucerne") and the credit line "Photo: ermell, CC BY-SA 3.0".
- **Form:** the heading is the screen's `h1` (serif, display size), with one sentence under it.
  - **Start step:** "Continue with Google", "or", Email, "Email me a code". There is no sign-up and no forgot-password, because Google or a code covers both cases.
  - **Code step:** "Check your email", "We sent a 6-digit code to …", and InputOTP 3+3. A back arrow beside the heading returns to the start step, and "Use a different email" does the same.
- **Every original state is kept, with the same state machine (`use-sign-in.ts` unchanged):**
  - any 6 digits sign in
  - `000000` gives a wrong code with tries left (UX proposal mark)
  - 5 wrong codes lock the slots and show "Send a new code" (proposal mark)
  - `999999`, or a real age over 10 minutes, gives an expired code
  - "Resend in 0:30" counts down, then "Resend code" unlocks
  - every send or resend mails N01
  - invalid email shows a field error
  - Google shows a pending state for 0.7 s
  - the code field takes focus after every code sent
- **Mail panel round trip:** the Mail panel opens from the prototype bar over the screen. Closing it leaves the code step as it was, because the screen stays mounted.
- **Leaving:**
  - **After sign-in:** the screen replaces itself with `returnTo` (`router.history.replace`), so Back from the next screen skips sign-in.
  - **Already signed in when opened:** it goes straight to `returnTo`.
  - **Back without signing in:** `history.back()`, so cancelling from cart Continue returns to C04, not C06. With no history it goes home.
- **`returnTo` safety:** only in-app paths are accepted (`/…`, not `//…`, not `/sign-in…`). Anything else falls back to `/account`.

### `useRequireSignIn` (API kept compatible)

- `requireSignIn(onDone?, returnTo?)`:
  - signed in: runs `onDone` at once, as before
  - signed out: navigates to `/sign-in` with `returnTo` set to the given path, or by default the current location
- **Cart:** passes `"/cart/review"`, so Continue lands on C06 after sign-in.
- **Callers that pass no arguments come back to the screen they were on, with no change needed:**
  - Account
  - C06 Send (decision 173 holds: the guest taps Send again)
  - order detail
  - pay
- **`signInSheet` is now always `null`.** It is kept so the five callers compile without edits, including `account.tsx`, which 1.12r owns. Callers can delete `{signInSheet}` whenever they next touch their files.

## 2. How I used the impeccable skill

- `.claude/skills/impeccable/scripts/impeccable context --target front-end/src/features/auth` loaded PRODUCT.md and reported `WORLD_DISCOVERY_REQUIRED`. Following the owner rule, I treated the design system, `theme.css` and the accepted decisions as the incumbent world. I ran no world discovery, wrote no DESIGN.md, and created no surface brief.
- **Mode:** Operate, because the guest is completing a task.
- I read `reference/new-work.md` §3: a whole surface inside an established world keeps the visual system fixed, and only the composition is open.
- `impeccable concept-seed --scope surface --mode operate` returned key `03e75cff`, dealing indices 6, 3 and 2. The owner had already pinned the composition: two columns, form plus Lucerne hero. new-work says a brief-pinned direction beats the roll, and the owner rule skips the decision page, so I did not serve it. The roll only decided the open axis, the phone arrangement, which I settled on the evidence below.
- I read `reference/craft-floor.md` before editing. What I applied from it:
  - no eyebrow or kicker above the heading
  - a single elevation per surface
  - 28px sheet and photo corners, matching the existing sheets
  - tight heading and intro grouping (8px) with wider gaps between groups
  - the existing focus ring and the shared `BackButton` and `BrandLogo` components
  - secondary text on the photo tinted white, not grey
- `impeccable detect --json sign-in-screen.tsx sign-in-form.tsx` printed `[]`, meaning no findings.
- **Token changes:** none. Only existing tokens are used: `bg-default/60`, `bg-background`, `shadow-overlay`, `text-display`, `text-title`, `text-body` and `muted`.

**Brief (recorded as I built it, per the owner rule):** a guest about to send a request or open their account is asked to sign in. The screen should feel like arriving in Lucerne, not like an interruption. The photo carries the place and the form stays plain and fast: Google first, email code second.

**Phone choice: hero on top, not as a background.**
- The code slots, the error text and the proposal marks need a plain surface to be readable. A photo behind them would need a scrim heavy enough to hide the photo.
- The phone keyboard shrinks the viewport, which would re-crop a background photo while the guest types.
- The overlapping rounded sheet repeats the bottom-sheet language the owner chose (decisions.tsv). It also keeps the photo and the content apart, as the discovery "Sky fade" hero does.
- The Google button stays above the fold at 375×812, and this is checked.

The crop keeps the tower roof in view on phones (`object-position 50% 14%`) and centres the photo on desktop (`50% 45%`).
