## 1. What I built

M02 at `#/store`, the same for Owner and Manager. Top to bottom on a phone (375px, stacked):

1. **Header:** "Today" and the short date.
2. **Needs attention:** only when there is something to chase. One card with a danger row "Payment overdue" and/or a warning row "Handed over, balance owed", each with a hint, a count and a link to the M03 tab. The overdue row keeps 1.9's rule: it opens the tab of the overdue order with the soonest pickup.
3. **To do tiles:** four tiles in one divided block: Awaiting confirmation, Awaiting payment, To prepare, Ready for pickup. Each tile has an icon, a large count and a name, and links to `/store/orders?status=…`. 2×2 on phones, four across from 1024px. A tile at 0 stays in place so the grid holds its shape, with a muted count, and is plain text rather than a link into an empty tab.
4. **Still to collect** (money): the total, then one stacked bar split by stage (awaiting payment / preparing / ready / balance owed). Each stage has a legend row with its order count and CHF amount, and each row links to that M03 tab. The parts add up to the total. When nothing is owed it shows "CHF 0.00 · Nothing owed right now."
5. **Next pickups:** preparing and ready orders, soonest pickup first, up to 5. Each row has a date tile (dark with "Today" when the pickup is today), guest, reference, gift, a `StatusChip` with the T0 staff progress label, and a link to M04 (`/store/orders/$orderId`). The header has an "All orders" link. When the list is empty the widget shows one line.
6. **Commission to pay** (money): the recorded total, recorded commission per partner, and a muted line "+ CHF x estimated on open orders" (accepted onwards).
7. **Completed this week:** the count, the Mon–Sun range, and two bars comparing the order value of last week and this week. This week is drawn lighter because it is still running. Each bar has its order count.

From 1024px the widgets under the tiles split into a wide column (collect, pickups) and a narrow column (commission, completed). The DOM keeps phone order, so Tab order matches what you see at both widths.

**States, all still reachable:** skeleton, seed, all six tasks, alerts only (all four tiles at 0), empty, and Owner.
- **Empty:** all six tasks are 0. The tiles are replaced by the original empty state ("No tasks. New requests will show up here." + "See all orders"), and the money widgets stay.

### Inspirations (WebSearch / WebFetch) and what I took

- **[Shopify Home](https://help.shopify.com/en/manual/shopify-admin/shopify-home):** order tasks come first, grouped by type with a count each, then the metric cards. → "To do" tiles with counts at the top, money widgets below, and the overdue/owing alert above everything.
- **[Shopify metrics card pattern](https://shopify.dev/docs/api/app-home/patterns/compositions/metrics-card.md):** each metric has a label, a value and an optional trend, and links to its detail report. Metrics sit side by side on wide screens and stack on narrow ones. Lists use dividers instead of boxed rows. → Every tile, breakdown row and pickup row is a link. Rows inside widgets use dividers.
- **[Airbnb host Today tab](https://www.rentalscaleup.com/what-airbnbs-new-today-host-tab-and-price-comparison-tool-with-booking-com-say-the-companys-priorities/):** "arriving soon / checking out" lists by date. → "Next pickups" with a date tile and a "Today" marker.
- **[Stripe Dashboard home](https://docs.stripe.com/dashboard/basics):** money and balance widgets with small charts, and comparison with the previous period. → "Still to collect" with a breakdown bar, and "Completed this week" compared with last week.
- **[Square Dashboard widgets](https://www.square.com/help/us/en/article/5183-square-dashboard-overview):** the sales widget compares the period with the same period last week, and clicking a widget opens its report. → The same week-on-week comparison, and click-through to M03.
