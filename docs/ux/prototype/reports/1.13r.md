# Step 1.13r: C15 Guest order detail, tabbed redesign (owner review follow-up)

Owner verdict on 1.13 (phase1-review-2026-10-13): "redesign the ui entirely, we should use tab-layout for better content focus instead of a long scrolling page. additionally, the ui is terrible".

## 1. What I built

**Layout.** The single long page is replaced by a fixed structure with three parts.

1. **Top bar.** Back, plus "Order SK-1044". It is sticky and translucent, as before.
2. **Pickup ticket.** This is the header and answers "what matters now". It is a white card with these parts:
   - A date tile: weekday, day and month of the pickup, muted on closed orders.
   - The gift name in serif, the pickup place, and whether the pickup is requested, confirmed or cancelled.
   - A thumbnail.
   - Both labels: the progress chip and the payment chip (T0 `useOrderSummary`, unchanged).
   - A dashed tear line, then one **headline** for the state with a tone icon and one sentence.
   - **The one next action**, in this priority: Pay (primary), Request again, or Write a review (`OrderReviews`, which opens the C18 sheet). Cancel order is a quiet ghost button under Pay.
   - Secondary notices sit under the ticket as Alerts: the R04 changed-place note, payment processing after cancellation, and money received after cancellation.
3. **Underline tabs.** These are sticky under the top bar, in HeroUI `Tabs` `variant="secondary"`, and are 44px high:
   - **Overview:** pickup date, place with address, opening hours with instructions, then the gifts as ordered with Total, Paid and Still to pay.
   - **Payments:** the payment label, the amounts, then the payment history (amount, method, time and status chip).
   - **Progress:** a stepper with logged steps (filled check, time), upcoming milestones (hollow dot, "Next") and the latest step in bold. The connector is solid between done steps and dashed toward upcoming ones.
   - **Policy:** the policy at the time of ordering, then contact. Contact holds the reference (selectable, Copy with "Copied" feedback), Email and Call.

The selected tab is in the URL (`?tab=payments|timeline|policy`), so reload keeps it (tested; back was not tested, and tab changes replace the history entry rather than adding one). The search param is optional and Overview is the default, so every existing link (C14 rows, C11 request sent, C12 return) still opens Overview.

**De-duplication.** In 1.13, the amount and deadline appeared three times above the fold: in the chip, the alert title and the alert body. Now the payment chip carries the amount and deadline. The headline names the consequence or the next step, and the button names the amount. The drive script checks that the deadline appears only once in the header. I rewrote these `guestOrder.notice.*` values in EN and DE:

| State | Old headline | New headline (body) |
|---|---|---|
| Requested | Waiting for the seller to confirm (repeated the chip) | Your request is with the seller |
| Payment due | Pay CHF 54.00 by … | Pay to keep this order ("If it isn’t paid in time, the order is cancelled automatically.") |
| Handed over with balance | CHF 62.30 still to pay ("Due by …") | Pay the rest online or at the shop ("The order is complete once it’s paid in full.") |
| Processing | Payment processing (repeated the chip) | Please don’t pay again |
| Preparing | The shop is preparing your order | The shop is preparing your gifts |
| Declined | The seller declined this request (repeated the chip) | Nothing was charged ("The seller’s reason: …") |
| Cancelled, overdue | Cancelled because the payment was overdue (repeated the chip) | The payment deadline passed |
| Cancelled by you | You cancelled this order (repeated the chip) | Nothing to refund ("Nothing was paid on this order. To still get these gifts, request them again.") |

**Every state of 1.13 is still reachable** the same way: Prototype controls → Add sample orders in every state (SK-1043 to SK-1050), the seeds SK-1012 and SK-1015, and Expire this order’s payment deadline. The reachable states are:

- requested
- payment due with the auto-cancel warning
- changed place with the R04 note
- preparing
- ready
- handed over with a balance
- completed with the review
- declined
- cancelled overdue with Request again
- cancelled by you
- payment processing
- received after cancellation
- loading, not found and signed out

**The Pay link to C12** is now a typed `<Link to="/account/orders/$orderId/pay">`. Before, it was a plain `#/…/pay` href, which 1.13 left for 1.14 to replace.

**Cancel** uses the shared `ConfirmDialog` (`useConfirm`). After confirming, focus moves to the new headline (`#order-headline`, `tabIndex=-1`) because Pay and Cancel disappear.

**The review** stays in the header action area, not in a tab. An unmounting tab panel would otherwise drop the sheet's state. `features/reviews` is unchanged.

## How I used the impeccable skill

- `impeccable context --target front-end/src/features/transactions/order-detail/components/order-detail.tsx` loaded PRODUCT.md. It reported WORLD_DISCOVERY_REQUIRED, no matching surface brief, and that a manual detector run was needed.
  - Following the worker brief, I treated the existing design system as the incumbent world: `theme.css`, `tokens.json`, decisions.tsv and the lab order-cards brief.
  - I skipped world discovery, `document` and the shaping or confirmation gates (owner rule of 2026-10-13).
  - I created no DESIGN.md.
- **Mode: Operate.** The guest is completing a task, so the work followed `reference/operate.md`: standard tabs, consistent component vocabulary, motion only for state, and a restrained palette with the accent only on the primary action and the selected tab.
- I read `reference/craft-floor.md` before editing. It shaped three decisions:
  - No eyebrow label above headings. The "requested/confirmed pickup" label sits under the place, not above the title.
  - No nested cards. Each tab panel has one surface level.
  - A single elevation: a 1px border, no shadow.
  - It also set the 44px touch targets and colour always paired with an icon and words.
- **Key design decisions:**
  1. **Ticket header.** It reuses the composition of the lab order-card candidate L ("pickup ticket": date tile and dashed rule), which the owner selected in the lab. That brief says L is a lab choice, not production-approved, so C15 is its first production use and needs the owner's approval.
  2. **A headline instead of an alert box** for the main state, with one consequence sentence. Only the extra notices stay as Alerts.
  3. **Underline tabs (HeroUI secondary).** Pill tabs would compete with the status chips.
  4. **Timeline stepper** with solid and dashed connectors.
- `impeccable detect --json order-detail.tsx account_.orders.$orderId.tsx` returned `[]`, with no findings.
- **Tokens:** no token changed. Only existing roles are used: surface, separator, muted, success, warning, danger, info and accent.
