# Step 1.15 report: M04 next step + M08 Record payment

## 1. What I built

**M04 "Next step" block** (`FulfilmentActions`). It fills the slot that 1.11 left for orders past `requested`. All transitions and guards come from T0 (`useOrderActions`, `completeBlock`, `useBlockText`, `balance`).

| Status | What the block offers |
| --- | --- |
| accepted | Record payment, for when the guest pays at the shop |
| preparing | **Mark as ready** (T0 `markReady` → N12), plus Record payment if money is owed |
| ready, owed | **Mark as handed over** (marked as the "Handed over" UX proposal), Record payment, and Complete locked ("Not handed over yet") |
| ready, paid in full | One button, **Handed over and complete** (T0 `handOverAndComplete`) |
| handed_over, owed | **Record payment** as the primary button. Complete is disabled, with "Complete is locked:" and a StatusChip "CHF 62.30 still owed" (`aria-describedby`) |
| handed_over, paid | **Complete order**, with the consequence: closes the order, invites a review, partner commission recorded once |
| completed | "Order completed · Completed by Lukas · 13.10.2026, 10:00", taken from the log row |
| requested / declined / cancelled | nothing (requested keeps 1.11's decision block) |

After each step, focus moves to the next enabled action, or to the block heading if there is none. This is because the button that was pressed disappears.

**M08 Record payment sheet.** It uses 1.11's `SheetFrame` Drawer.
- "Still owed: CHF 62.30"
- **Amount**: NumberField in CHF, defaults to the balance. There is no `maxValue`, so an amount above the balance is not silently clamped.
- **Method**: cash, bank transfer, other.
- **Received at**: TimeField, 24h. It defaults to the demo time when the sheet opens and is capped at that time. A later time disables the button. The help text reads "Today, 13.10.2026".
- **Note**: optional. It now shows in the M04 payment row.
- **Button** names the consequence for each method: "Record CHF 62.30 cash. Balance will be CHF 0.00." / "… by bank transfer …" / "… (other method) …".
- **Above balance**: field error "More than the CHF 62.30 still owed" from T0, and the button is disabled.
- **Duplicate** (T0: a succeeded payment with the same amount within 10 minutes): a warning Alert with T0's "CHF 26.70 was already recorded at 13.10.2026, 10:00. Record it again?". The button changes to "Record CHF 26.70 cash again. Balance will be CHF 35.60." Pressing it sends `allowDuplicate`.
- After saving, a success toast reads "CHF 62.30 recorded. Balance CHF 0.00."

## 5. Open questions for the owner

1. **Duplicate vs outline wording.** Outline step 14 says "recording the same amount again within 10 minutes shows the duplicate warning". T0 checks the balance first, so recording CHF 62.30 again after the balance is CHF 0.00 shows "More than the CHF 0.00 still owed" (and the button is hidden anyway). The duplicate warning shows when the same amount still fits, for example CHF 26.70 cash right after the online deposit. Should the outline be reworded, or should a duplicate show even when the balance would go negative?
2. **Confirming Complete.** Should Complete, which records commission and is final, also get a confirmation sheet, or is the consequence line under the button enough?
3. **Time field.** Should M08 allow an earlier day (for example, money received yesterday), or is today only enough for Phase 1?
