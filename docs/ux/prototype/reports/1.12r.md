# Step 1.12r: Account hub (owner review follow-up to 1.6 part 2 and 1.12)

Owner verdict on 1.6 (part 2) and 1.12: "redesign the account screen properly, it supposed to let users manage their bookings/orders/payment info/profile, not just transactions history".

## 1. What I built

The Account tab is now an account hub:
- **Profile header**: initial avatar, name in Source Serif, the full email (it no longer truncates) and a Sign out button under the email.
- **Four underline tabs**, the same `Tabs variant="secondary"` that C15 uses: **Orders · Bookings · Payments · Profile**.
- The tab lives in the URL as `?tab=` (`#/account?tab=payments`). Orders is the default, so every existing link to `/account` still opens the order list.
- The tab list sticks to the top while scrolling.

| Tab | Content | States |
|---|---|---|
| Orders (C14) | **Coming up**: open orders as small pickup tickets (date tile, gift, place, then both labels and the R04 note below a dashed rule, then ref and total), soonest pickup first. **Past orders**: closed orders (completed, declined, cancelled) as quieter rows with both labels, newest first. Every order opens C15. | skeleton, seed (past only), open + past, R04 note, empty, keyboard focus |
| Bookings | Honest empty state: "Tour bookings will show here. Tours come later." No action, because `/tours` is itself a placeholder. | empty (Phase 2) |
| Payments | **Due now**: open orders with `amountDueNow > 0`, each with T0's payment label, linking to C15. **Payment history**: every payment across the guest's orders, newest first, showing amount, order ref and gift, method and time, and a status chip (Received / Processing / Failed / Received after cancellation from T0's `paymentsAfterCancellation`). Each row opens C15 on its Payments tab. **Saved payment methods**: a dashed placeholder, "Not in the prototype. No card is stored. You pay each order on the payment provider's page." | due + history, history only, no payments |
| Profile | **Personal details**: name is editable in a bottom sheet (empty name blocks Save; the header updates); email is read-only ("You sign in with this address."). **Language**: English / Deutsch radios that switch the app (`setLanguage`), with the note that order emails keep the order's language (spec §6). **Trip profile**: the C07 `TripProfile` card on `useTripProfile`: "Not answered yet" + Answer now → form → saved summary with Edit. **Emails we sent**: the last 3 guest emails from the demo mail log (subject in the email's own language, time), each opening its order. | unanswered, form, answered, name sheet (valid/invalid), no emails |

The signed-out state keeps 1.6's prompt. Sign in calls `useRequireSignIn().requireSignIn(undefined, "/account")`, which opens 1.6r's C05 screen at `/sign-in?returnTo=/account` and comes back to Account; the drive checks this. Per the coordinator's follow-up I removed `signInSheet` (always `null` since 1.6r) from `account.tsx`.

**Payment info and the PRD.** The PRD (lines 153, 161, 276) states that tours without prepayment need no card, that the system does not by default store a card or charge it automatically, and that no card guarantee is required at booking. It names Stripe only as a candidate (line 282). So the prototype stores no card. The tab shows real payment data from the orders and a clearly labelled saved-methods placeholder.

## 3. Touched outside my files

- **`front-end/src/features/checkout/components/trip-profile.tsx`** (step 1.8, additive): new optional prop `skippedText?: string` on `TripProfileProps`. When set, the card shows it instead of `t("tripProfile.skipped")` ("You skipped the trip questions."). C07 does not pass it, so C07 is unchanged. The account hub passes `status="skipped"` plus this text when nothing has been answered. This avoids the C07 "Skip" button on a page where skipping means nothing.
- **i18n keys of other steps, used read-only:**
  - `guestOrder.method.*` and `guestOrder.paymentStatus.*` (1.13): the method and status words in Payments
  - `tripProfile.*` (1.8): through the card
  - `auth.account.title`/`signedOut*` (1.6): signed-out branch, unchanged
- **Renaming in the demo store renames the guest everywhere.** M03/M04 and P02 read the name from `guests[]` by id, so a presenter who renames Anna on the Profile tab changes those screens too. Reset restores it.
- **The C07 link "See all in My transactions"** (`features/checkout/components/request-sent.tsx`, 1.8) still links to `/account` and lands on Orders. Its wording now names a heading that no longer exists. I left it; 1.8 owns that copy.

## 6. Open questions for the owner

1. **Email editing.** I kept email read-only because it is the sign-in identity. Do you want an "change email" flow (send a code to the new address) in a later step?
2. **Language preference.** The radios switch the app language for this browser. Should the account also store a preferred language for future emails? Today each order's emails follow the language it was ordered in (spec §6), and `Guest` has no language field.
3. **C07 link copy.** "See all in My transactions" (1.8) could become "See all in Orders" / "Alle Bestellungen ansehen" to match the hub.
4. **Seed.** A fresh seed gives Anna only past orders, so "Coming up" appears only after a request (or the fixture). Should the seed give her one open order so the hub shows both groups on first sign-in?
