### Rules

- **Required text.** A published gift must keep one complete language: all of name, story, cancellation policy and option names in English, or all in German. Since [Revision 1](#revision-1-owner-15102026), a draft saves with less. Otherwise Save is blocked:
  - a danger note appears;
  - the empty fields of the closer language are marked "Needed for the English version.";
  - that tab is selected, and focus moves to the first empty field.
- **DE missing is a warning.** With English complete, a missing German field only shows the warning; Save goes through and the gift stays published (R02). C03 in German then shows the English text with its language notice. M11 shows "DE missing".
- **Numbers.** Each number field has a range. An empty or out-of-range field is marked "Enter a number from 1 to 40." after a save attempt.
- **Stock.** Stock can't go below the units accepted orders hold. For example, SK-1028 holds 1 Large knife: "Accepted orders hold 1, so stock can't be lower."
- **Pickup places.** At least one must stay chosen.
- **Refresh.** The draft lives in the screen, so a refresh drops unsaved edits and keeps what was saved (outline side path).

### Decisions to confirm (revision 1)

- **Stored as Tiptap JSON, not HTML.** Guests' screens render the JSON from a fixed list of nodes and marks (`components/rich-text.tsx`), without `innerHTML` and without a sanitizer to keep current. Links are filtered again when rendered.
- **A custom photo node instead of `@tiptap/extension-image`.** The node has one `photo` attribute: a library slug, or an uploaded data URL. The stock image node stores `src`, which for library photos is a hashed asset URL that breaks with the next build. Only `@tiptap/react`, `@tiptap/pm` and `@tiptap/starter-kit` (v3, React 19) were installed. The editor loads lazily, so only M12 and M13 load Tiptap.
- **The story sheet's layout changes slightly.** The chapter numbers ("01", "02") are gone. The seeded chapters became a photo, a heading and paragraphs, so the text and photos are unchanged.
- **One heading level.** The editor has no strike, underline, code or horizontal rule.
- **Photo limits.** At most 1200px and 300,000 characters per photo (about 220 KB), with a storage budget of 4.5 million characters. These are prototype limits for localStorage. A real upload would go to storage instead.
- **Option names moved** from the text tabs to the Options card, with English and German side by side.
- **Deleting a never-ordered draft is not built.** It was optional, and it would need the shared confirmation dialog.
- **Reused component with an inaccurate note.** Content-track's photo sheet says photos come from the library "instead of an upload". That is not true next to M12's "Upload photo". I flagged it and did not edit their file.
