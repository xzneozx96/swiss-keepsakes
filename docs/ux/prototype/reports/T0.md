### How screens use it

```ts
const actions = useOrderActions();
const block = actions.complete(order.id);           // null = done
if (block) show(useBlockText()(block).text);        // "CHF 62.30 still owed"
const { progress, payment, balance } = useOrderSummary(order);
<StatusChip tone={payment.tone}>{payment.text}</StatusChip>
```

To show a lock before the tap (for example the Complete button disabled with its reason), call the guard: `completeBlock(order)`, `acceptBlock(state, order)`, `recordOfflinePaymentBlock(order, input)` and so on. C12 uses `actions.payOnline(id, "succeeded" | "failed" | "processing")`. The prototype bar uses `actions.expirePaymentDeadline(id)` and `actions.resolveOnlinePayment(id, outcome)`. The values for the M04 accept confirmation come from `firstPaymentAmount(order)` and `dueDatesAtAcceptance(order, now)`.

**Call one action per user step.** An action checks its guard against the state from the last render. If one click handler calls `handOver` and then `complete`, `complete` still sees `ready` and returns `not-handed-over`. The combined button must call `handOverAndComplete`.

## 5. Open questions for the owner

1. **Automatic overdue cancel.** The demo clock runs in real time, so a seeded 24-hour deadline never passes during a demo. Overdue cancel happens only through "Expire this order's payment deadline", as the outline says. Should a real-time sweep also cancel an order whose deadline passes? My default is no.
2. **Overpaying a deposit order.** "Deposit paid · …" is still shown when more than the deposit is paid but a balance remains (for example SK-1021 after two CHF 20.00 cash payments). Should it switch to "Paid CHF X · CHF Y left"?
3. **Late money for a cancelled order.** Is "Received after cancellation · awaiting reconciliation" (the payment label only, no email) enough for flow 1? Spec N22 exists only for tours.
4. **Emails for offline payments.** A payment recorded on M08 sends no email (N07 and N21 are tied to online payments in outline §3). Should cash payments also send an N07 receipt?
5. **Date-time format in the browser.** `formatOrderDateTime` was checked in Node only ("14.10.2026, 10:30" in both en-CH and de-CH). Chrome's ICU can differ from Node's. The first screen step that shows a deadline should confirm the comma before the time.
