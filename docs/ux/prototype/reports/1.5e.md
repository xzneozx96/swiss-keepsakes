# 1.5e: C04 cart, owner feedback after 1.5d

## 1. What I built

### 1. Space above the bottom bar

**Root cause, measured** (`1.5e-measure.mjs`, 375×812, 3 lines, scrolled to the end, before the change):

| | px |
| --- | --- |
| Fixed bottom bar height | 109 |
| Cart content `pb-36` | 144 |
| Guest shell `<main>` `pb-[calc(safe-area+88px)]` | 88 |
| Reserved in total | 232 |
| Gap between the last card and the bar | **124** |

The cart reserved space twice. It added its own 144px, and the guest shell padded `<main>` for the tab bar even on `hideTabBar` routes, where no tab bar is shown. Neither number followed the bar's real height. The bar is 109px with the old layout and taller when the blocked message shows. Screenshot of the old state: `screens/1.5e/before-gap-en.png`.

**Fix (coordinator chose option B):**
- New opt-in route flag `staticData.ownsBottomSpace`. With it, the guest shell adds no bottom padding, and `<main>` becomes a flex column so the screen can fill the height.
- `/cart` sets the flag.
- The cart bar is now `sticky bottom-0` at the end of the cart's own flow (no `fixed`, no `pb-36`). The space after the last card is the list's normal `pb-5` (20px), the same as `gap-5` between sections. Because the bar is in the flow, the space follows its real height.
- With little content, the content area grows (`flex-1`), so the bar still sits at the bottom of the screen.

**After** (`1.5e-drive-*.out`):

| State | Bar height | Gap last card → bar |
| --- | --- | --- |
| EN, 3 lines | 117 | 20 |
| EN, blocked message shown | 145 | 20 |
| DE, 3 lines | 117 | 20 |
| DE, blocked message shown (wraps to 2 lines) | 165 | 20 |
| Invalid-date line | 117 | 20 |

`<main>` padding-bottom is 0px on `/cart`. In EN the bar's bottom edge is reported 1px above the viewport bottom. This is sub-pixel rounding of the scroll position; DE reports 0.

### 4. Info Alert
- **Why not a HeroUI prop:** HeroUI 3.2.6 `alert.css` has only status colour modifiers (indicator and title colour). It has no tint or variant, so a modifier class is needed.
- **The pattern is one reusable place in `styles/components.css`:** the `alert--soft` modifier. Add it to any HeroUI Alert.
- **What it does:**
  - a status tint background
  - a 1px border in the status colour at 25%
  - no shadow
  - icon and title in the status colour
  - the description in `--muted`
- **Variants:** warning, danger, success and accent come from HeroUI's own status class. Info is `alert--soft alert--info`, because HeroUI has no info status; the caller passes `InfoIcon`.
- **C04 note:** `<Alert className="alert--soft alert--info">` with the circle-i InfoIcon. Computed:
  - background rgb(230,238,248) (`--info-soft`)
  - border 1px info at 25%
  - icon and title rgb(31,95,168) (`--info`)
  - body rgb(94,94,90) (muted)
  - shadow none
- **The same pattern on the invalid-date Alert** in the card. It was inline `bg-warning-soft shadow-none`; it is now `alert--soft status="warning"`. This shows the pattern works for C15's auto-cancel warning and others.
- **Amber or info?** Info. The note explains how the cart works (dates are requests, orders split, pay later). Nothing is wrong and nothing needs action. Warning amber is kept for states that need the guest to act, such as the invalid date on the same screen. If the note were amber too, the real warning would no longer stand out.

**Kept:** the 1.5d selection behaviour (ticks, Select all indeterminate, persistence), the ConfirmDialog on remove, QuantityBox, the invalid-date state and its fix, the empty state, the skeleton, and the card surface (`rounded-3xl bg-surface p-4 shadow-surface`, no border).

## 5. Open questions for the owner

1. Store name on every line: with one shop it repeats the same name on every card. Keep it for when there are several shops, or show it once above the list until then?
2. The highlighted price is the unit price ("CHF 54.00 each"). For quantity 2 or more, should the line show the line total instead (or as well)?
3. The design-system Alert card still says "never tinted". Should it be updated to the `alert--soft` pattern for all info, warning and danger notes, or only where a screen asks for it?
4. The bar counts lines ("2 of 3 selected") and the cart badge counts quantities (4 with the knife at quantity 2). Is that difference fine, or should both count the same way?
