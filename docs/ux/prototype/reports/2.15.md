How the scripts work:

- **Labels.** Labels come from the live `en.ts`/`de.ts` plus every `features/**/messages.ts`, so each script asserts the real copy in the language it runs in. The prototype bar stays English by design.
- **Per-screenshot checks.** Every screenshot also checks:
  - horizontal overflow is 0 (100 screenshots; merchant ones also at 1024px);
  - no raw message key and no literal `{param}` is visible;
  - no image has finished loading with zero pixels (a broken image);
  - in DE (50 screenshots), no English UI string is visible and no German label is clipped. A label counts as clipped when it is wider than its box. Screen-reader-only text and one seeded staff note ("Bank transfer, ref. YT-1012", free text) are excluded from these two checks;
  - labels cut on purpose with an ellipsis (`truncate`) are listed separately as `INFO` lines for review (§3).
- **Errors.** Every run checks that the console and page show no errors. Map tile network noise from OpenFreeMap is filtered out.

Screenshots are in `screens/2.15/` as `<step>-<screen>-<state>-<lang>.png` (`g` guest, `m` merchant, `c` checks).

## 9. Open issues and caveats

- **Overdue check runs only while a merchant screen is open (known caveat).** Before any merchant screen opens, the guest's C16 shows "Balance overdue", not cancelled: `caveat: before any merchant screen, guest C16 shows 'Balance overdue', not cancelled`. Opening M02 runs the check, and the guest then sees the cancellation: `caveat: opening M02 runs the check…`, `caveat: guest C16 then shows cancelled, 'Paid · nothing more owed'`. A backend job would run it on time.
- **Old demo data needs Reset (known caveat).** Stored data from before a fixture change keeps its old departures until Reset: `old stored demo data stays until Reset (known caveat): 23 Oct missing`, then `after Reset the 23 Oct departure is back`. `DEMO_VERSION` was not bumped by rule.
- **P02 wording.** P02 counts tour bookings under "Orders" and in "+CHF … estimated on open orders" (8 orders and CHF 79.30 with tours; 6 and CHF 11.30 without). Owner: should these say "orders and bookings"?
- **Lint.** 167 formatting and import-order warnings remain in `src/i18n/en.ts`/`de.ts` (not tour files; not fixed, as the run is without `--fix`).
- **Build.** The map library chunk is 1.05 MB (285 kB gzip) and triggers Vite's chunk-size warning. C09 could load it lazily if size matters for the pilot.
- **Phase 1 copy on tour screens (unchanged):**
  - C12's provider page says "Order reference" and "Back to your order" on tour bookings.
  - The reused trip profile on C13 mentions pickup dates.
- **M07 group line** shows "Infants 0" when no infant is booked (worker C's screen; cosmetic).
- **M02 tour names truncate at 375px in DE** in "Nächste Termine". The truncation is deliberate and the full name is one tap away. The owner may prefer two lines.
- **Phase 1 drivers to refresh.** `1.18-*`, `1.12r`, `1.12s`, `1.17r` and `1.9s` still encode superseded behaviour. A Phase 1 owner should retire or re-baseline them, or the next complete-flow check will report the same stale failures.
- **Simulations.** The last-seat race, provider results, session closure and late reconciliation are simulated in one browser. They need backend and provider verification before launch.
