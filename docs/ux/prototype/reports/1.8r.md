## 1. What I built

### Extraction (C06 has no visual change)

- New `features/checkout/components/order-card.tsx`. It holds C06's order card, moved without change from `review-view.tsx`: `OrderGroup` became `OrderCard`, `ReviewItem` became the internal `OrderItem`, and the `ReviewOrderView` and `ReviewItemView` types moved with them.
- `OrderCard` has two optional slots, `status` (under the title) and `footer` (the last row), plus a `headingLevel` prop.
  - C06 passes neither slot, so they render nothing.
  - `headingLevel` defaults to 2 (order h2, gift h3, as before). C07 passes 3, so the cards nest under its "Your orders" h2.
  - Class names and the `review-<key>` heading id are unchanged.
- `review-view.tsx` now imports `OrderCard`. It re-exports both types, so the lab files (`routes/lab.review.tsx`, `features/lab/review-order-options.tsx`) still compile unchanged.
- Before editing, I checked that `review-view.tsx` was unchanged since my read (mtime 20:54, same content).
- **Proof:** a pixel diff of C06 before and after with `magick compare -metric AE` gives **AE = 0** for all four captures: EN full page, DE full page, cancellation policy open, and the price-details sheet.

### C07 Request sent (`features/checkout/components/request-sent.tsx`)

- **Header:** a 56px success icon, "Request sent" and the intro (singular and plural forms kept). The intro moved up from `text-sm` to body size.
- **Your orders:** each created order is the C06 `OrderCard`, in the same order and with the same titles the guest just saw ("Order 1", "Order 2"). Everything C06 showed is still there: request date, place, payment type, gifts with option and engraving, the amount due after the seller confirms, the order total, the deadline rule and the cancellation policy. C07 adds:
  - `status` slot: "Reference SK-1043", then the T0 progress chip ("Awaiting seller confirmation") and payment chip ("Nothing to pay yet").
  - `footer` slot: a "View order SK-1043 ›" row that opens C15. The card is not wrapped in a link, because it contains the cancellation accordion button.
- **Language notice:** when a gift name or cancellation policy is shown in the other language, the same soft info alert C06 shows appears above the cards. It uses the existing `checkout.onlyInEnglish` / `checkout.onlyInGerman` keys (R02, AC30). The seeded limited-edition print is English only, so this case is reachable in the demo.
- "See all in My transactions" (C14) stays under the cards.
- **What happens next:** a vertical timeline in the same white card (`rounded-3xl bg-surface shadow-surface`) instead of a flat numbered list. Each step has an icon node, a title and a short body, and the nodes are joined by a line.
  - Step 1, "The seller confirms each order", is the current step: it has an info-tinted node, a "Now" pill and `aria-current="step"`. This matches the order's "Awaiting seller confirmation" chip.
  - Steps 2 ("You pay per order") and 3 ("You pick up your gifts") use neutral nodes.
- **Trip profile** (`trip-profile.tsx`): the same white card, divided into header, questions and actions, instead of the outlined box.
  - Travel style is shown as two tiles with icons (group / on my own). They are still a React Aria `RadioGroup`, so arrow keys and the radio role work. The selected tile gets an ink border and a tinted fill.
  - Arrival and departure are the two halves of one date field, as in booking apps ("Arrival | Departure", short labels). Each half opens the same bottom-sheet calendar as before. The accessible name is the full label plus the value, e.g. "Arrival in Lucerne, Add date".
  - Actions: Skip / Back as a ghost button, Save answers as a tertiary button. This keeps the screen's only red, filled button the sticky "Back to Explore".
  - **Answered:** "Edit answers" moved into the card header. The body shows a green "Thanks, your answers are saved." and an icon row per answer; unanswered values are in muted text.
  - **Skipped:** one row, with the text on the left and "Answer now" on the right.
  - The props contract is unchanged (`status`, `answers`, `onSave`, `onSkip`, `skippedText`), so the account hub keeps working.
- **Loading skeleton** (`routes/_guest/cart_.sent.tsx`): it now matches the new shapes (icon, title, intro, section title, two tall cards).

### Hook (`features/checkout/hooks/use-request-sent.ts`)

- `SentOrderView` is now `{ id, ref, card: ReviewOrderView, progress, payment }`.
- The hook also returns `languageNotice`. It collects `isFallback` from `pickText` for product names and cancellation policies, as `use-review.ts` does.
- `card` is built from the stored order with the same keys and T0 selectors that C06 uses: `cart.order.title`, `cart.policy.*`, `cart.line.requestDate`, `checkout.item.quantity`, `checkout.order.*`, `checkout.rule.*`, and `orderTotal` / `firstPaymentAmount` / `lineTotal` / `dueDatesAtAcceptance`.
- I did not change `use-review.ts`, because it is C06's hook and the owner may be editing it. As a result, the order-to-card mapping now exists in both hooks (see open question 2).
