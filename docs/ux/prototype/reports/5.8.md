# 5.8 M24 Cost data

Step 5.8 of [the Phase 5 checklist](../todo-phase5.md). Skill: evon, "just build it" path. All new files except the strings.

## Brief

Owner or Manager opens M24 to enter the actual costs of completed transactions, so M21 can show contribution margin (R14). The page leads with how complete the data is, lists the transactions still missing costs first, and each one opens a sheet to fill in.

## Test-harness note

With the Orca window off screen, `element.blur()` did not trigger React's `focusout`, so a typed amount did not commit and one test save went through with the fee still missing. Dispatching `focusout` (what a real tap elsewhere produces) committed it. The app is not affected; checks of number fields must dispatch `focusout`.

## Revision 1 (owner review, 14 October 2026)

**What the screen is for:** a sale shows revenue, not profit. M21 shows contribution margin (profit after each sale's variable costs) only from real, complete costs (R14), so M24 is where staff enter each completed sale's goods, packaging, payment fee, delivery and other costs, and where they see which sales still lack them.

- **Chart instead of the progress bar (owner's choice):** "Cost data per week": completed sales per week for 8 weeks, stacked into all costs entered (ink) and costs missing (warning colour), with a tooltip. Tapping a bar, or one of the week buttons under it (keyboard and screen readers), narrows the list to that week and shows a "Week of 5 Oct ×" chip; tapping again shows every week. The week is in the URL.
- **Rows in the M03 card style (owner's choice):** product or tour photo, name (+n more), guest and date, amount; the reference is small text linking to M04/M07; the state chip and Enter or Edit costs stay.
- Checked at 375px (DE): 8 week buttons, the current week showing 3 missing; tapping 5 Oct → 21 sales, chips 0 / 21 / 21, scroll kept; tapping again → 135. Loaded at phone width the chart fits (284 px) with no horizontal scroll.
- Note: resizing an already-drawn chart under browser emulation left Recharts at the old width; it fits whenever the page loads at the phone width, and the Overview charts behave the same.
