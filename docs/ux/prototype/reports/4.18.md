## Note open items

- **Regression note: test fix, not an app fix.** The first DE run of `2.15-guest` failed one check: "C09 View more opens the stop sheet". The cause is that the M23 reply (4.16) on a seeded tour review is long enough to show the review card's "Show more". In German that button and the map card's "View more" are both "Mehr anzeigen", and the script clicked the first match, which opened the reviews sheet. The app is correct. `reports/2.15-guest.mjs` now scopes the click to the map card, and it passes in both languages. Two buttons on one screen with the same German name is a small accessibility smell. A clearer label for one of them, for example "Antwort ganz lesen" for the review card, is open for the owner.

## Decisions to confirm, all steps

Each step's report has the details.

**4.7 Trip profile**
1. C23 stays dropped. Trip answers live on each order and booking (2.17).

**Products (4.8–4.11)**
2. One price set per tour, shown on every departure. Departures have no price field, and the booking flow reads tour prices.
3. Options and pickup points can't be added or deleted, because orders point at them. An option is switched off with "For sale" instead. Departures change seats only.
4. When a gift has every pickup place ticked, nothing is stored, so a place added later is offered too.
5. The number limits are placeholders: engraving up to 40 characters, commission up to 50%, up to 200 seats.
6. Unpublishing a gift or tour asks nothing, because it can be undone.
7. Mails show the current pickup-point text, so an older mail shows the hours after an M14 edit. Choose: copy the text into each mail when sent, or accept it for the prototype.
8. A draft gift still opens from a direct link and can be added to the cart from there. A draft tour already shows "not found". Should gifts match?

**Content (4.12, 4.13, 4.16)**
9. The Owner's public name: "Ngọc" on new replies, but "Chị Ngọc" on the seeded review reply. Pick one.
10. Read time is computed on save, so the Pilatus draft goes from the seeded 4 minutes to 1.
11. "Add German/English version" creates a draft copy for translation. An article's language is fixed after the first save.
12. Unpublishing an article asks first, and so does removing a section or a block with content. Removing a link or a picked story asks nothing.
13. An unpublished linked item stays in the list with a warning and still counts toward the 6.
14. Publishing again moves the story to the top of C19.
15. Hiding a comment hides its replies and asks nothing; deleting asks first and deletes the replies. Shop replies can also be hidden or deleted.
16. Review replies record their language. Editing a reply updates its author and date. There is no "remove reply".
17. No paging: Reviews has 89 cards and Comments 43 on a phone. Choose a default filter (for example "Not replied") or paging.

**Requests (4.14, 4.15, 4.17)**
18. Question edits save at once; there is no "publish the set" step. They apply to new conversations only.
19. A missing translation is a warning, never a block. Changing a question's type clears its options.
20. A new recipient address also applies to the next N16 from a conversation started earlier.
21. M20 uses "Mark answered" with Undo instead of a confirmation, and has no detail page.
22. N17 languages: the prototype assumes the Owner reads English and the Manager German, because staff have no stored language. Older staff mails still go as one "Shop staff" mail in the interface language. Align them later?
23. N16 keeps the guest's question wording as asked, so a German question can appear in the English mail.
24. C21 change: an optional number question now offers Send with the shown value as well as Skip. It only matters once a number question is made optional in M19.

**General**
25. In German, the map card's "View more" and a review's "Show more" are both "Mehr anzeigen" on C09. Rename one?
