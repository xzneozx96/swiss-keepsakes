## Decisions to confirm

- **One price per tour, not per departure.** The spec lists "price per departure", but a departure has no price field. The guest flow reads the tour's adult, child and infant prices in five places: C09, C10, C11, `tourTotal` and the booking snapshot. So M13 edits the tour's prices next to the age groups, and each departure row and the new-departure sheet show that price. A per-departure price needs a field on `Departure` and changes to those five places in the tour booking flow. See the doc changes below.
- **Itinerary text only.** Stops can be renamed and rewritten, not added or removed: a new stop would need a map position and a photo for C09.
- **Inclusions.** "Add item" adds one. An item emptied in both languages is removed on save, so there is no separate delete button and no confirmation dialog.
- **Existing departures: seats only.** Changing the start would leave bookings with the old time. Cancelling a departure is Phase 3 (money operations).
- **Departures save at once, the rest with the save bar.** A departure is its own record that M05 and C10 read, so its sheet saves it and a toast confirms. The note on the card says so.
- **New departures have no overdue rule.** "The merchant decides" is the default when the balance deadline passes (R07), as for most seeded departures.
- **Deposit is 30%,** the fixed sample rate the booking flow uses (`firstPaymentAmount`).
- **The upper limit is 200 seats** per departure (my placeholder).

### Review the changes

- **Seven steps:** Basics (photo, duration, name, summary, description) · Itinerary & details (itinerary, inclusions, exclusions, meeting point, conditions) · Prices & age groups · Departures · Policies & commission · Story · Review & publish.
