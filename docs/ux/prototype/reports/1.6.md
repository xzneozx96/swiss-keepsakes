# Step 1.6 report: C05 sign-in sheet, Account tab, Mail panel, Show proposals

## 1. What I built

### C05 sign-in sheet (bottom sheet, Drawer card)

- **Start step:** "Continue with Google" (simulated, about 0.7 s pending, then signed in), "or", an Email field, and "Email me a code". The email is prefilled with the demo guest's address (`anna.keller@example.com`) to speed up demos. An invalid address shows a worded field error.
- **Code step:** "Check your email" and "We sent a 6-digit code to …". A labelled InputOTP ("Code from the email", 3 + 3 slots) has a description that gives the 10-minute lifetime. The code field takes focus whenever a code is sent. A back arrow and "Use a different email" return to the start step.
- **States:**
  - **Any 6 digits:** signs in. The 6th digit submits automatically; "Continue" does the same.
  - **`000000`:** wrong code, with a worded error and "N tries left for this code". The tries count is marked as a UX proposal.
  - **5 wrong codes:** locked. The slots are disabled, and "Too many wrong codes. Send a new code to try again." appears with a "Send a new code" button. Marked as a UX proposal.
  - **`999999`, or a real age over 10 demo minutes:** expired, with "Send a new code".
  - **Resend:** shows "No email? Resend in 0:30" with a 1 s countdown. The link is disabled until the countdown ends.
  - **Every send or resend:** sends a new N01 and clears the tries.
- **On success:** `data.signedInGuestId = "g-anna"` (Anna Keller), the sheet closes, and the caller's `onDone` runs.
- **State survives closing:** the sheet's state stays when it is closed. The presenter can close it, read N01 in the Mail panel, reopen it and still be on the code step.

### API for step 1.7 and later

The API lives in `features/auth/hooks/use-require-sign-in.tsx`:

```tsx
const { requireSignIn, signInSheet, signedIn } = useRequireSignIn();
<Button onPress={() => requireSignIn(() => navigate({ to: "/cart/review" }))} />
{signInSheet}   // the caller renders the sheet; no provider needed
```

- When the guest is already signed in, `requireSignIn(onDone)` runs `onDone` immediately.
- Otherwise it opens the sheet and runs `onDone` after sign-in. The cart is not touched.

### Account tab (`routes/_guest/account.tsx`)

- **Signed out:** the title "Account", the heading "Sign in to see your orders", one sentence, and a "Sign in" button that opens C05.
- **Signed in:** an initial avatar, the name, the email and "Sign out". Signing out sets `signedInGuestId` to null.
- **C14 slot:** step 1.12 has already added its `<TransactionList />` in the slot I left, and the signed-out state still works.

### Mail panel (prototype bar: an envelope icon with a count)

The button shows only the icon and count; its accessible name is "Mail, N emails". A word did not fit at 375px with a merchant role.

- A bottom drawer with Guest and Staff tabs. Emails are listed newest first, and each one is a `<details>` card (the newest is open) showing:
  - the template code
  - the recipient's language
  - the send time (Zurich)
  - the subject, the "To:" line and the body
- Every email is rendered in **its own `language`**, not in the language the prototype UI shows. The panel imports the `en` and `de` dictionaries directly.
- T0's raw params are formatted for the reader:
  - Rappen become money
  - `dueAt` becomes "14.10.2026, 10:35"
  - `pickupDate` and `dueDate` become "20.10.2026"
  - `pickupPlaceId` becomes the place name, address, hours and instructions
- Copy covers every flow-1 template:
  - guest: N01, N02, N04, N05, N06, N07, N08, N12, N15, N23
  - staff: N03, N21, N23
- Any other template falls back to its code plus `key: value` lines, so it stays readable.

### Show proposals

- A switch in the Prototype controls drawer, stored in localStorage `sk.showProposals` and kept outside the demo data, so Reset does not change it.
- `<ProposalMark name="…">` wraps any element that rests on an undecided UX proposal. When the switch is on, the element gets a dashed violet outline and an "UX proposal: …" tag. The tag text uses the i18n key `proto.proposal`.
- It is used on the tries-left line and on the locked state.

### Sign-in codes hint

The Prototype controls drawer has a "Sign-in codes" note for presenters: any 6 digits work, 000000 gives a wrong code, and 999999 gives an expired code.
