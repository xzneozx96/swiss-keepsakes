# M20 Private tour requests

15 October 2026. Step 4.15 is built and awaiting the owner's batch review.

Built directly in the React app with evon ("just build it"), matching the M03 list (tab with count, phone ticket, desktop table) and M15's card action bar.

## Review the changes

Switch to **Merchant · Owner** (or Store Manager, D12), open Requests and the **Private tours** tab (`#/store/requests?tab=private`; N17 links here). Try it in EN and DE.

- **Inbox, newest first.** The tab count is the number of requests, as on M03.
- **Phone ticket (M03).** Each request shows:
  - the date tile of the first preferred day;
  - the guest's email;
  - **New** or **Answered**, with the guest's language and the time sent;
  - Group ("6 people"), Dates ("24.10.2026 – 25.10.2026", or one date for a single day) and Interests ("None given" when left out).
- **Actions (D9).** The ticket ends in M15's action bar with two small ink buttons:
  - **"Reply by email"** is a `mailto:` with a subject in the guest's language. The reply itself happens outside the app.
  - **"Mark answered"** sets the answered time by hand. A toast confirms it and offers **Undo**.
  - Once answered, the bar shows "Answered on 13.10.2026, 10:00" instead of the button, and the date tile turns grey.
- **Table from 1024px.** The columns are:
  - Guest: the email, which is the reply link, with the language and time.
  - Group and dates.
  - Interests, two lines with the full text on hover.
  - Status: the chip, and the answered time.
  - "Mark answered", in its own column.
- **Empty state.** One sentence ("No private tour requests yet. They appear here when a guest asks for a private tour.") and "Back to Overview".
- **From C22.** A request sent on `/tours/private-tour` appears at the top as New. N17 goes to the Owner and the Manager (step 4.17).

## Decisions to confirm

- **No confirmation for "Mark answered", Undo instead.** Marking a request answered loses nothing, so it doesn't use the delete-style dialog. Undo in the toast reverses a mistap. There is no "mark as new" later; ask if the shop needs it.
- **Ink actions, not red.** A list of tickets each with red buttons would compete. The actions use M15's small tertiary buttons, and the screen has no red primary action.
- **No detail page.** The outline lists no route for one, and the ticket already shows everything the guest sent.
- **The date tile is the first preferred day**, as M03 uses the pickup day. It is the date the shop plans around.
