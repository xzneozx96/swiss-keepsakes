# 1.5f: C04 option and engraving rows; bottom-bar spacing on C06, C07, C03

## 1. What I built

### 1. Option and engraving on the C04 cart line
- The muted "Small · Engraving “Ross Geller”" line under the name is gone. Option and engraving now sit with the other icon rows, at the top of the group, because they describe what the guest gets.
- **I chose two rows, one fact per row:**
  - the option ("Small" / "Klein") with a tag icon (new `OptionIcon`, `Reicon.Tag`);
  - the engraving ("Engraving “Ross Geller”" / "Gravur «Ross Geller»") with the pen-nib `EngraveIcon` that C03 already uses for engraving.
- **Why two rows:** a single row would need one icon for two different things. Two rows also keep long engravings from wrapping into the option.
- **Row order on a line:** option, engraving, request date, pickup place, payment rule.
- A gift with a single "Standard" option and no engraving shows neither row. The gift box shows only date, place and payment.
- A one-option gift with an engraving shows only the engraving row, and a gift with options but no engraving shows only the option row.
- **Verified line text (EN):** "Kapellbrücke pocket knife | Swiss Keepsakes Luzern | Small | Engraving “Ross Geller” | Request to receive on Wed 21 Oct | Shop Altstadt | Full payment after confirmation | CHF 49.00 | each".
- The remove confirmation text still reads "1 × name · option · engraving (CHF …)".

### 2. Bottom-bar spacing on the other no-tab-bar routes
Same fix as C04 in 1.5e:
- the route sets `staticData.ownsBottomSpace`, so the shell adds no 88px tab-bar padding;
- the screen root and content grow to fill the screen (`flex-1`);
- the bar changes from `fixed` to `sticky bottom-0`, at the end of the screen's own flow;
- the content keeps only its own section spacing at the bottom.

Because the bar is in the flow, the space follows its real height. On short content the bar still sits at the bottom of the screen.

**Measured** with `1.5f-measure.mjs`: 375×812, scrolled to the end, EN and DE identical. The gap runs from the lowest visible content to the bar top, or to the screen bottom when there is no bar. "Before" is the code as it was at the start of this task (`1.5f-before.out`); "after" is the final code (`1.5f-after.out`).

| Route | Bar | Reserved before | Gap before | Change | Gap after |
| --- | --- | --- | --- | --- | --- |
| C04 cart (1.5e) | 117 sticky | — | 20 | already fixed in 1.5e | 20 |
| C06 review | 109 | own `pb-44` 176 + shell 88 = 264 | **155** | `pb-44` → `pb-5` (= its `gap-5`) | **20** |
| C07 request sent | 69 | own `pb-32` 128 + shell 88 = 216 | **147** | `pb-32` → `pb-8` (= its `gap-8`) | **32** |
| C03 gift detail | 93 | shell 88 only | **11** (last 5px of the content sheet under the bar) | own `pb-4` kept | **16** |
| C15 order detail | none | shell 88 | 136 | not changed (no bottom bar) | 136 |
| C12 pay | none | shell 88 | 88 | not changed (no bottom bar) | 88 |

- **C03:** the generic metric reads −5 before and 0 after, because C03's content sheet has a background and counts as content. The table uses the last accordion row instead, measured by `1.5f-c03.mjs` (`1.5f-c03.out`).
  - Before is measured on the old layout, emulated with injected CSS (fixed bar plus 88px main padding): 11px.
  - After: 16px.
  - The bar is 93px, taller than the 88px the shell reserved, so the sheet's bottom edge was hidden under the bar.
- **C15 and C12** have no fixed bottom bar, so they fall outside this task's condition and I left them unchanged. Their end space includes 88px of shell padding for a tab bar they don't show. If the owner wants that gone too, setting `ownsBottomSpace` on those two routes is a one-line change on each.
