# Step 1.12s: Account hub in the social-media settings style, with profile photo

The owner's verdict on 1.12r: "the account page looks terrible, especially the payment page, pls reference to account setting from social media like facebook, instagram for reference, users should be able to upload avatar as well".

## 0. Research: patterns taken from Instagram and Meta

Sources:
- Meta's Meta Pay help article (official): https://www.meta.com/help/meta-pay/559736935834154/. It gives this path on Facebook for iPhone and Android: Menu → **Settings & Privacy** → **Settings** → **Accounts Center** → under **Account settings**, **Meta Pay** → "manage your payment methods". It says payment activity lives in a separate **Orders and payments** hub.
- Instagram Help Center: the page (help.instagram.com/iphone-app/369207764224422) did not render through fetch. Search-result excerpts of help.instagram.com say the name, username and profile picture are edited in **Accounts Center → Profiles**, or from the profile through **Edit profile**.
- Third-party 2026 guides describe the menu as **Settings and activity** (gear icon, first item). They disagree on exact labels ("Change profile photo", "Remove current photo", "Remove profile picture"). I could not open the live app.

I therefore take these as conventions, not quotes:

| Pattern (Instagram / Meta) | Taken as |
|---|---|
| Profile header: large round photo, name, handle or email, an **Edit profile** button | Hub header: 96px round avatar (initials if no photo), name in Source Serif, email, an "Edit profile" pill |
| Settings as **grouped lists**: section heading, then rows with icon, title, one-line description and chevron | Four white rounded groups on the warm ground, hairlines inset past the icon |
| Each row **drills into its own screen**, with a back arrow and a centred title | `AccountScreen`: sticky bar with ← and the screen name |
| A separate **Edit profile** screen with the photo on top and "Change photo" / "Remove photo" under it, fields below | `?tab=edit`: 112px photo with a camera badge, Change photo, Remove photo, Name, read-only email, Save |
| Picking a photo opens a **move and zoom** step before it is used | Bottom sheet "Position your photo": drag or arrow keys to move, Zoom slider, Save photo |
| Payments as **rows that drill in** (Meta Pay → payment methods; Orders and payments → activity), not one dense panel | Hub row "Payments and history" → Payments screen: Due now, history by month, Payment methods |
| The account photo **on the profile tab** of the tab bar (Instagram) | Account tab shows the photo with an accent ring when active, and the icon when there is no photo |
| **Log out** as its own row at the bottom | "Sign out" in its own group at the bottom |

## 1. What I built

**Route**: still one route, `/account`. The sub-screen lives in `?tab=`.
- No `tab`: the hub.
- `orders`, `bookings`, `payments`, `profile`, `notifications`, `edit`: one sub-screen each.
- The 1.12r values (`orders | bookings | payments | profile`) are a subset, so every 1.12r deep link still works without a redirect. That includes the tour flow's `navigate({ to: "/account", search: { tab: "bookings" } })`.
- An unknown value falls back to the hub.
- Rows push history. Browser Back and C15's `history.back()` return to the sub-screen they came from. The sub-screen ← goes back, or to the hub when there is no history (a deep link).
- I did not add new route files. `account_.orders.tsx` would become the parent of C15 (`account_.orders.$orderId.tsx`), and C15 has no `<Outlet/>`.

**Hub** (signed in). Every row shows one live line, so the hub shows what needs attention without a tap:
- **Header**: avatar (photo or initials), name, email, Edit profile.
- **Your activity**:
  - Your orders: count, plus "Next pickup Mon 19 Oct · Kapellbrücke pocket knife", "Nothing to collect right now" or "No gift orders yet".
  - Tour bookings: count, plus "Next tour …", "No upcoming tours" or "No tour bookings yet". The data comes from the Phase 2 tours store.
- **Payments**: "Payments and history" with "CHF 64.00 due now" (the icon tile turns accent-soft) or "Nothing due · payment history".
- **Profile and preferences**:
  - Edit profile: "Photo, name and email".
  - Language and trip: "English · Trip profile open".
  - Emails and notifications: the latest email's subject, in that email's language.
- **Sign out**: its own group.

**Avatar upload** (`features/account/lib/avatar.ts`, `avatar-crop-sheet.tsx`, `edit-profile.tsx`):
- **Opening the picker**: Change photo or the photo itself opens the file picker (`accept="image/*"`).
- **Checks, in order**:
  1. The MIME type starts with `image/`: "That file isn't a photo…".
  2. Size ≤ 2 MB: "This photo is 3.4 MB. Choose one up to 2 MB."
  3. The image decodes: "This photo can't be opened here…" (for example HEIC in Chrome).

  An error shows in a `role="alert"` box. The next valid pick clears it. The input resets, so the same file can be picked again.
- **Crop sheet**:
  - a round 248px frame; the photo always covers it, and the crop is clamped
  - drag with the pointer, or arrow keys while the frame has focus
  - a Zoom slider from 1× to 3×
  - Save photo draws the visible square to a **256px JPEG data URL (quality 0.85)**, about 22 KB in the drive, and stores it as `guests[].avatar` through `useDemo().update`
  - Cancel discards it; the object URL is revoked either way
- **Remove photo** asks first in the shared `useConfirm` dialog ("Remove your profile photo?" / "Remove photo"), then initials return.
- **Shared `GuestAvatar`**: shows the photo, or initials ("Anna M. Keller" → "AK") on ink. It is used in the hub header, in Edit profile and in the tab bar.
