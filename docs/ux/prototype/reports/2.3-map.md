# Step 2.3-map: itinerary pins on C09 (owner request, 14 October 2026)

Worker A. The owner's reference is Wanderlog's "Trip to New York": a large map, and a floating card for the selected place inside the map. The guest never leaves the map to read about a stop. Design pass: impeccable in refinement mode on the existing map, with no shaping gates. I kept the project tokens, HeroUI, MapLibre and the OpenFreeMap style.

## 1. What was there and what I changed

**Before:** a 400–420px map, then below it a numbered stop list and a stop detail block (photo, time, name, description). Reading a stop meant scrolling between the map and the blocks below it.

**Now (`features/tours/map/tour-itinerary-map.tsx`, `.css`, `messages.ts`):**
- **Taller map:** `min(72svh, 640px)`, at least 460px; 585px at 375×812. The map, the card and the attribution fit between the compact top bar and the sticky "Choose a departure" bar, so reading a stop needs no page scroll.
- **Map unchanged in substance:** MapLibre, OpenFreeMap Liberty, 3D buildings, the dashed red route, numbered pins, Whole route, the 2D/3D toggle, fullscreen and zoom/compass. The zoom/compass group moved from bottom-right to under the fullscreen button at top-right, so the card does not cover it.
- **Stop card inside the map,** near the bottom edge:
  - the red numbered disc, matching the selected pin;
  - "Stop 2 · 25 min into the tour";
  - the place name in bold serif (Source Serif names places);
  - the description clamped to 2 lines with an ellipsis;
  - a 76px square photo on the right;
  - an action row: previous, "2 of 4", next, and "View more";
  - a round close button floating above the card's right edge.
- **One selection** drives the pins, the card and the sheet:
  - tapping a pin selects its stop;
  - previous/next in the card or the sheet selects the stop, highlights its pin red and flies the map there;
  - the camera offset keeps the pin in the open map area above the card.
- **The ends disable** (my choice; the brief allowed wrap or disable):
  - **Rule:** on stop 1, Previous is disabled; on the last stop, Next is disabled.
  - **Why:** a walking route has a start and a finish, and wrapping from the lake back to the bridge would suggest a loop.
  - **Focus:** when the pressed button becomes disabled, focus moves to the other button, so keyboard focus is never lost.
- **"View more"** opens the full stop in the project's existing sheet: `SheetFrame`, the HeroUI `Drawer` frame from the merchant decision block, reused without edits. No new drawer was built.
  - Heading: the stop name.
  - Body: the 16:10 photo, "Stop 3 · 65 min into the tour", the full description and a "Good to know" note when the stop has one.
  - Footer: Previous stop / Next stop, which keep the map selection behind the sheet in sync.
  - Close button, Escape and backdrop all close it, and focus returns to "View more".
- **Closing the card** deselects the stop and moves focus to that stop's pin. Each pin is a keyboard-focusable button, so Enter on it reopens the card.
- **Announcements:** a `aria-live="polite"` line reads "Stop 3 of 4: Musegg Wall" on every change. The sheet has its own live line, because the page behind a modal is hidden from assistive tech.
- **Fullscreen** uses MapLibre's CSS ("pseudo") fullscreen on the whole map frame (`FullscreenControl({ container: frame, pseudo: true })`):
  - The card and the Whole route/3D buttons come along into fullscreen.
  - The sheet still opens above it: the HeroUI overlay sits at z-index 100000, above MapLibre's 99999.
  - Native element fullscreen would hide the sheet, and iPhone Safari does not offer it for a map anyway.
  - Escape leaves fullscreen as it would natively. While the sheet is open, Escape closes only the sheet.
- **Removed:** the below-map stop list and the stop detail block, as requested. The gesture hint and "Sample itinerary · the line connects stops, not walking directions." stay below the map.
- **Attribution** stays MapLibre's compact control, at 10px on one line below the card, and collapses to the ⓘ button after the first map drag.
- **New and changed strings** (DE in Sie): previous/next stop, "{n} of {count}", View more, Close stop details, Good to know, the live line, and a new subtitle "Tap a numbered pin to explore each stop.". The error text now reads "…You can still step through every stop below."

**Bugs found and fixed along the way:**
1. **"Whole route" zoomed out to all of Switzerland** after a stop had been selected. MapLibre keeps the `padding` passed to `flyTo` as map padding and adds it to `fitBounds` padding. The free space vanished, so the map zoomed out to the minimum. Fix: `flyTo` now uses a pixel `offset`, and only `fitBounds` uses padding.
2. **After toggling fullscreen in DE, the control was labelled "Exit fullscreen" in English.** MapLibre rewrites the label from the strings it got at map creation. This was there before this task. Fix: the fullscreen state is tracked from the control's events, and a separate effect puts the translated labels back.
3. **The stop card vanished when opening another tour's detail page without leaving it.** The map component kept the previous tour's selected stop. Fix: `discovery/tour-detail-page.tsx` keys the map by tour id.
4. **The selected pin turned pale pink under the mouse.** Hover now applies only on hover-capable devices and never overrides the selected red.
5. **The pins and map controls painted over the "map could not load" message.** The loading and error overlays now sit above them and below the card, so the stops can still be stepped through when the map is down.

## 6. Open questions for the owner

- **Should `SheetFrame` move to `src/components/`?** It lives in merchant code, so the guest map imports a merchant module and the sheet's close label uses the merchant key ("Close"/"Schliessen"). Moving it is a shared-file change for the coordinator.
- **The sheet heading is sans-serif** (`SheetFrame` uses `text-title`), while the card uses serif for place names as the design system says. Should it switch to serif?
- **Native fullscreen or the current CSS fullscreen?** CSS fullscreen keeps the browser toolbar on desktop. Native fullscreen would hide the "View more" sheet and is not available on iPhone.
- **Sample notes need Reset.** In a browser that already holds demo data, the stored itinerary is kept, so the new "Good to know" notes appear only after Reset demo.
- **Card close behaviour.** Closing the card leaves the map where it is. Should Whole route run automatically on close?
