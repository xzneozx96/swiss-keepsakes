# Step 1.12t: default profile photo for the demo guest

The owner asked to "use a fake avatar similar to the review comments on profile".

## 1. What I built

**Source.** The review list's reviewer photos (`features/catalog/components/review-item.tsx` → `useProductReviews` → `lib/avatars.ts` `avatarUrl(name)`) come from SVGs in `src/assets/avatars/`:
- style: DiceBear 9.x **"Notionists"** by Zoish
- licence: **CC0 1.0**
- seed: the reviewer's short name ("Lena K.")
- a background from an 8-colour pastel set

I confirmed the recipe by refetching `seed=Lena K.`: the drawing is byte-identical to the stored `lena-k.svg`; only the background differs.

**New asset.**
- `src/assets/avatars/anna-k.svg` was fetched from `https://api.dicebear.com/9.x/notionists/svg?seed=Anna%20K.&backgroundColor=` with the same 8 pastels. It came out with the `#dfe3ee` background.
- Its embedded metadata names Zoish and CC0. It has no scripts and no external links.
- I added the credit to the existing **`src/assets/avatars/CREDITS.txt`**, the file that covers the reviewer avatars. `src/assets/photos/CREDITS.txt` covers the photo set, so it was not the new file's home.

**Seed.** `demoGuest` in `features/orders/seed.ts` now has `avatar: "sample:anna-k"`, a reference rather than a URL.
- `GuestAvatar` resolves `sample:<slug>` to the bundled asset with the same `avatarUrl` lookup the reviews use. Any other value is treated as an uploaded data URL.
- Why a reference:
  1. The seed is also loaded outside Vite by the `tsx` self-checks. `T0-selfcheck.ts` crashed with `import.meta.glob is not a function` when the seed imported `lib/avatars`, and passes again with the reference.
  2. localStorage never holds a build-hashed asset URL that could go stale.

**DEMO_VERSION 11 → 12** (`features/demo/seed.ts`). Stored v11 data has no photo for Anna, so without a bump a browser that already ran the demo would keep showing initials. The drive confirms that v11 data is replaced by the v12 seed with the photo. This also resets every presenter's local demo data once.

**Behaviour** (no other code change needed; it uses the 1.12s flows):
- The photo shows in the hub header, on the Edit profile photo and on the Account tab of the tab bar.
- Change photo replaces it with the uploaded, cropped JPEG.
- Remove photo is offered for the default too. It asks through the shared ConfirmDialog, then falls back to initials, and the tab bar goes back to the icon.
- Reset demo restores `sample:anna-k`.

**Files changed**
- `front-end/src/assets/avatars/anna-k.svg` (new) and `front-end/src/assets/avatars/CREDITS.txt` (one line appended)
- `front-end/src/features/account/components/guest-avatar.tsx`: resolves `sample:` references
- `front-end/src/features/orders/seed.ts`: `avatar` on `demoGuest`
- `front-end/src/features/orders/types.ts`: doc comment on `Guest.avatar`
- `front-end/src/features/demo/seed.ts`: `DEMO_VERSION = 12`
- `docs/ux/prototype/reports/1.12t-drive.mjs`, `1.12t-drive.out`
