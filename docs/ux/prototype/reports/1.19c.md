# 1.19c Review gallery page

## 1. What I built

- `screens/phase1-review/build-review.mjs`: a Node script with no dependencies. It reads `items.json` and whichever of `manifest-guest.json` and `manifest-merchant.json` exist, then writes `index.html`.
- `screens/phase1-review/index.html`: one self-contained page. CSS, JS and data are inline, image paths are relative, there are no web fonts and it makes no network requests. It works when opened from disk (`file://`).
- No product code changed under `front-end/src`.

**Rebuild command** (run once 1.19a and 1.19b have written their manifests and images):

```sh
cd docs/ux/prototype/screens/phase1-review && node build-review.mjs
```

`node build-review.mjs path/a.json path/b.json` builds from other manifests instead. `file` in every manifest is resolved against `phase1-review/`, whichever folder the manifest sits in.

**Manifest validation.** The schema is the one the coordinator confirmed: an array of `{item, file, caption, lang: "en"|"de", width: 375|1024, issue?: string}`. The script exits 1 and names the file and index of the first problem. Examples:

- `manifest-guest.json[3]: width must be the number 375 or 1024`
- `…[0]: item "9.9" is not in items.json`
- `…[0]: file img/nope.png does not exist (resolved against phase1-review/)`
- `…: must be an array`
- `issue` set to anything other than a non-empty string
- unknown fields
- invalid JSON
- duplicate ids in `items.json`

If no manifest exists, the build still succeeds and every item shows "No screenshots for this item".

**Page contents:**

- **Header:** title "Phase 1 review" and the build time.
- **Sticky summary bar:**
  - counts for Approved, Not approved and Not reviewed
  - filters: All, Not reviewed, Approved, Not approved
  - "Copy as text" and "Download review" (red, the only accent fill on the page)
- **One white card per item, in `items.json` order:**
  - id chip, title and status pill
  - a link to the item's report, or "no report" when the file did not exist at build time (1.4 today)
  - a thumbnail grid with captions and EN/DE and width chips. 1024px shots span two columns. Shots with an `issue` get an amber border, an "issue" chip and the issue text.
  - two big toggles, "Approved" (green when on) and "Not approved" (brick when on). Clicking the active one again clears it.
  - a comment box. While an item is Not approved with an empty comment, the box is tinted and a hint shows.
- **Viewer:** a native `<dialog>` with Prev/Next buttons, arrow keys, and Esc or Close. It moves through the screenshots of one item only, shows the issue text, and returns focus to the thumbnail when it closes. Phone shots are shown at their real CSS width rather than stretched.
- **Saved state:** verdicts and comments are saved to `localStorage` under `phase1-review:<build time>`, with every read and write wrapped in try/catch. A "Reset verdicts" link at the bottom asks for confirmation first.
- **Download review** saves `phase1-review.json`:
  ```
  {reviewedAt, items:[{item, title, verdict: "approved"|"not_approved"|null, comment}]}
  ```
  Every item is included. An empty comment is `""`.
- **Copy as text** copies one line per item, `1.9 M02 Merchant Today: Not approved`, followed by an indented `Comment:` line when there is one.
- **Blocked export:** while any Not approved item has no comment, both buttons stop. A red notice names the items ("Add a comment to every Not approved item first: 1.9."), and the page scrolls to the first one and focuses its comment box.
