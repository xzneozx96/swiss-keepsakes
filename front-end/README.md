# Swiss Keepsakes prototype

A clickable prototype of Swiss Keepsakes for the client. It has no backend, and all data is mock data held in the browser.

## Stack

- React 19, Vite and TypeScript.
- HeroUI v3 (`@heroui/react`, `@heroui/styles` 3.2.6) on Tailwind CSS v4. There is no provider, and components are compound (`Card.Header`). Use `onPress`, not `onClick`.
- TanStack Router with file-based routes in `src/routes/` and hash history. The build is static, so URLs look like `#/merchant/orders`.

## Commands

```bash
pnpm install
pnpm dev             # the SPA alone. Sign-in needs the API: run `pnpm dev` at the repo root instead, which starts both
pnpm build         # type-check + production build into dist/
pnpm build:artifact # build + dist/artifact.html for publishing as a claude.ai Artifact
pnpm lint
```

The route tree in `src/routeTree.gen.ts` is generated by the Vite plugin. Keep it committed so `tsc` works on a fresh clone, and don't edit it.

## Structure

```
src/
  routes/       route files only: thin, they compose features
  features/     one folder per area (components/, hooks/, types.ts, index.ts)
  components/   shared primitives (RouterLink, status chips, money)
  contexts/     app-wide providers (language)
  i18n/         en.ts is the source of truth; de.ts must have every key
  lib/          pure helpers (formatting, safe storage)
  styles/       globals.css, theme.css (HeroUI variables), components.css (agreed overrides)
```

## Design rules

The design system is in `../docs/ux/design-system/project/` (README, tokens and component cards).

- `src/styles/theme.css` maps the approved tokens onto HeroUI's own variables. Change colours there, not in components. It already covers the warm neutrals, the visible 1px field border, the ink focus ring, the darker accent hover and the status colours, including info.
- `src/styles/components.css` holds the agreed departures from HeroUI that are already built: the ink destructive button (`variant="danger"`), and fields that are 40px on phones and 36px from `md`.
- Every other departure is still to build, at the point a screen first uses that component. Each one is listed under "Our changes" in `docs/ux/design-system/project/components/<Name>/README.md`. Read that section before using a component. The main ones are:
  - Status labels are always a soft `lg` Chip with an icon and words.
  - Selected tags, toggles and segments get a check icon and an outline.
  - Links are underlined.
  - Toasts with an action or an error stay until closed.
  - Progress bars are ink.
  - Switch and slider tracks get an outline.
  - Tap areas are 44px.
  - Drawers handle the safe area.
  - Sheet and dialog footers stack below 360px.
- Never pass a raw `href` to a HeroUI component (Tabs, Breadcrumbs, Menu or ListBox items, Pagination). Wrap it with TanStack's `createLink` first, as `RouterLink` does. A raw path skips the hash router and breaks on static hosting.
- There is one light theme. HeroUI's dark-theme variables are pinned to light values on purpose.
- Use `font-serif` with `text-display`, `text-title` or `text-card-title` only for places, products and stories. Everything else is Inter.
- Format money and dates with `src/lib/format.ts` (`CHF 1’249.00`, `14.10.2026`). Use `tabular-nums` for figures.
- For links inside the app, use `RouterLink` (HeroUI Link plus TanStack `createLink`).
- German copy is Swiss German: "ss", never "ß".
